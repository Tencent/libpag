# PAGX → PAG 基线测量与验收指标（M0-8）

> 测量日期 2026-10-22 ｜ 环境：Apple M4 Pro（macOS 15），Debug 构建（cmake-build-debug），桌面端。
> 测量工具：`test/src/PAGXPerfTest.cpp`（env 门控，默认跳过；兼作 T7 趋势基准 harness）、
> `pagx embed`、`pagx render`、`/usr/bin/time`。
> 手机端文本排版耗时无设备可测，先以桌面比例为参照，四期平台接入时补测（§13.3-5 允许）。

  文本信息本身的倍率与设计文档 §11 的估算（25–80×）一致。运行时排版方案的体积优势成立。

## B. 加载耗时基线（XML 导入 + 布局，324 样本 × 5 次取中位）

| 阶段 | 中位 | P90 | 最大 | 语料总和 |
|---|---|---|---|---|
| XML 导入（读文件 + 解析 + 建树） | 0.085 ms | 0.45 ms | 1.77 ms | 60.2 ms |
| applyLayout（约束求解 + 文本排版） | 0.005 ms | 0.69 ms | 6.19 ms | 116.2 ms |
| 合计 | — | — | — | 176 ms（≈0.54 ms/样本） |

- **文本排版主导布局耗时**：耗时 Top5 全部是文本样本（vertical 6.19 ms、box_layout 5.95 ms、
  line_break 4.28 ms、emoji 4.25 ms、富文本 3.72 ms）。v4 的加载期布局与 XML 路径走同一实现
  （§4.2 扁平化），该部分耗时不变；收益只能来自"二进制解码替代 XML 解析"。

## C. 内存基线

方法：`/usr/bin/time -l pagx render` 进程峰值（含 OpenGL 上下文与图片解码），重样本参考：
space_explorer 61.1 MB、nebula_cadet 53.4 MB、vertical 51.9 MB。
v4 对比沿用同方法；文档常驻另按节点/字节计数对比（零拷贝 ImageTable 需文件缓冲常驻，§5.1）。

## E. PAGXOptimizer 实测结论（§4.1 决策依据）

- XML 总体积 690,630 B → 572,921 B = **83.0%**（-17%）；265/324 个样本变小。
- 节点总数 10,994 → 11,064（+0.6%，路径改写为图元的包装开销，体积收益来自更紧凑的图元表达）。
- 优化后导入/布局耗时与原始相当（TSV: opt_import/opt_layout 列）。
- **结论：默认开启**。收益明确、无耗时回归；渲染等价性由一期对比页（T1，324+57 样本）验证。
  布局扁平化后布局节点消失，可优化结构更多，一期验收时重新实测并保留关闭开关。

## F. 旧 PAG 特性分布（迁移优先级参照；扫描结论来自设计文档 §6/§7.4 的 pag::File 全量扫描）

- 常见且已有对应：路径/形状、文本（描边/填充/竖排/框文本）、预合成、轨道蒙版、时间偏移/倍速
  （样本 3–5 个/特性）；混合模式、投影/内阴影/模糊广泛存在。
- 低频需新增：运动模糊、音频、置换、径向模糊、马赛克、辉光、动态拼贴、色阶、边角定位——
  各只出现在 1–13 个样本；3D 与相机**无样本**（仍按 C34 全量实现，验收靠构造样本）。
- 视频/位图序列：少量样本但主导旧语料体积（10.9 MB 最大者），三期 §6.6 实现后单独验收。
- Marker：样本中存在，按 C35 跳过并记录。

## G. 量化验收指标（各期验收对照；测量方法与本文基线一致）
